# بسلامت | BeSalamat

فروشگاه اینترنتی لوازم و تجهیزات پزشکی — فارسی، راست‌به‌چپ، لوکس (سبز + سفید)، همراه با پنل مدیریت کامل و معماری White-label.

## امکانات

- 🛒 فروشگاه کامل: کاتالوگ با فیلتر، صفحهٔ محصول با گالری زوم، سبد خرید، تسویه حساب
- 🔐 ورود با OTP (کد یک‌بارمصرف) + سشن سرور-محور (کوکی httpOnly)
- 🎛 پنل مدیریت کامل در `/admin` (داشبورد، محصولات، دسته‌ها، برندها، سفارش‌ها، کاربران، صفحهٔ اصلی، مقالات، تنظیمات)
- 📱 کاملاً واکنش‌گرا (موبایل-اول) + پوستهٔ روشن/تیره
- 🔍 سئوی فارسی: متادیتا، Schema.org (Product/Breadcrumb/Article)، sitemap و robots
- 💳 درگاه پرداخت ترب (حالت Sandbox) + درایورهای پیامک (کاوه‌نگار، ملی‌پیامک، SMS.ir)

## استک

| لایه | فناوری |
|---|---|
| فریم‌ورک | Next.js 16 (App Router) + TypeScript 5 |
| استایل | Tailwind CSS 4 + shadcn/ui + آیکون‌های Tabler |
| دیتابیس | Prisma ORM + SQLite (قابل تبدیل به Postgres/MySQL) |
| انیمیشن | Framer Motion + Embla Carousel |
| جدول‌ها | TanStack Table | نمودارها: Recharts |

## راه‌اندازی لوکال

```bash
bun install            # نصب وابستگی‌ها (prisma generate خودکار اجرا می‌شود)
bun run db:push        # ساخت دیتابیس SQLite
bun run db:seed        # دادهٔ اولیهٔ کامل (محصولات/دسته‌ها/اسلایدها/…)
bun run dev            # http://localhost:3000
```

فایل `.env` را از `.env.example` بسازید. برای ورود به پنل مدیریت، شمارهٔ داخل `ADMIN_PHONES` را با کد دمو وارد کنید.

## ورود به پنل مدیریت (دمو)

1. به `/login?admin=1` بروید (یا مستقیم `/admin` — به ورود هدایت می‌شوید)
2. شمارهٔ موبایل whitelist شده را وارد کنید (پیش‌فرض دمو: `09120000000`)
3. کد تأیید دمو: **`12345`** (تا زمان اتصال پیامک واقعی؛ با `OTP_DEMO_MODE=false` غیرفعال و کد تصادفی واقعی صادر می‌شود)

## استقرار روی ورسل (از طریق گیت‌هاب)

1. ریپو را روی گیت‌هاب Push کنید و در [vercel.com](https://vercel.com) → **New Project** → ریپو را انتخاب کنید (فریم‌ورک Next.js خودکار تشخیص داده می‌شود).
2. Build Command پیش‌فرض (`next build`) را دست نزنید — اسکریپت `postinstall` (پرایما ژنریت) خودکار اجرا می‌شود.
3. **متغیرهای محیطی** (Settings → Environment Variables) حداقل:
   - `OTP_PEPPER` — یک رشتهٔ تصادفی ۳۲+ کاراکتری
   - `SESSION_SECRET` — یک رشتهٔ تصادفی ۳۲+ کاراکتری (امضای کوکی سشن)
   - `ADMIN_PHONES` — شمارهٔ(های) ادمین
   - `DATABASE_URL` — *اختیاری؛ توضیح پایین*
4. Deploy. تمام!

### دیتابیس روی ورسل — خطاهای رایج و راه‌حل‌های پیاده‌شده

این پروژه برای رایج‌ترین خطاهای دیتابیس ورسل پیش‌بینی شده است (`src/lib/db.ts`):

| خطا | علت | راه‌حل این پروژه |
|---|---|---|
| `P1003: Database file does not exist` | فایل SQLite داخل باندل لامبدا نیست | `outputFileTracingIncludes` در `next.config.ts` فایل `db/custom.db` را داخل باندل می‌برد + مسیر با `pathToFileURL` مطلق ساخته می‌شود |
| `Error: unable to open database file` | فایل‌سیستم لامبدای ورسل فقط‌خواندنی است | در ران‌تایم، فایل یک‌بار به `/tmp` (تنها مسیر نوشتنی) کپی و اتصال به آن برقرار می‌شود |
| `P1001: Can't reach database server` | DATABASE_URL اشتباه/نرسیدنی | اگر `DATABASE_URL` به پایتایپ واقعی (Neon/Turso/PlanetScale) تنظیم شود، مستقیم استفاده می‌شود |
| `@prisma/client did not initialize` | generate روی سرور اجرا نشده | اسکریپت `postinstall: prisma generate` در نصب ورسل اجرا می‌شود |
| داده‌ها بعد از مدتی پاک می‌شوند | نوشتن در SQLite ورسل «ایفمرال» است — هر لامبدا فایل خودش را دارد | برای دادهٔ ماندگار، یک دیتابیس ابری (پیشنهاد: [Neon](https://neon.tech) یا Turso) بسازید و `DATABASE_URL` آن را در تنظیمات ورسل بگذارید — هیچ تغییری در کد لازم نیست |

### احراز هویت روی ورسل — سازگار با serverless

هر Route Handler روی ورسل یک لامبدای جدا با فایل‌سیستم جدا است؛ رکورد OTP/سشنی که یک لامبدا می‌نویسد در لامبدای بعدی دیده نمی‌شود. برای همین:

- **تأیید کد دمو stateless است**: در حالت دمو (`OTP_DEMO_MODE=true`)، کد ثابت `12345` بدون نیاز به رکورد DB در هر لامبدایی پذیرفته می‌شود. با `OTP_DEMO_MODE=false` مسیر امنِ رکورد-محور (سقف تلاش، انقضا، مصرف یک‌بارمصرف) برمی‌گردد — در آن حالت حتماً `DATABASE_URL` ابری تنظیم کنید.
- **سشن کوکیِ امضاشده است**: کوکی با `SESSION_SECRET` (HMAC-SHA256) امضا می‌شود و اعتبارسنجی بدون state مشترک انجام می‌شود؛ رکورد DB همچنان برای ابطال فوری/مسدودی نوشته می‌شود و با DB ابری کامل عمل می‌کند.

> **خلاصه:** بدون تنظیم `DATABASE_URL`، استقرار دمو با SQLite باندل‌شده کار می‌کند (ورود با کد دمو، سشن امضاشده، نوشتن ایفمرال). برای محیط واقعی، دیتابیس ابری وصل کنید.

## تغییر برند (White-label)

کل هویت بصری در دو فایل متمرکز است: `src/app/globals.css` (توکن‌های رنگ/سایه) و `src/config/brand.ts` (نام، لوگو، تماس، سوشال). متن‌ها و تنظیمات فروشگاه نیز از پنل مدیریت (`/admin/settings`) قابل تغییر است.

## ساختار مهم

```
src/
├── app/            # صفحات (App Router) — /admin پنل مدیریت
├── components/     # کامپوننت‌های UI (shadcn/ui در components/ui)
├── server/         # منطق سرور: OTP، سشن، درایورهای پیامک/پرداخت، آپلود
├── lib/            # ابزارها، دیتابیس، دادهٔ پیش‌نمایش
└── config/brand.ts # هویت برند
prisma/             # اسکیمای ۲۵+ مدل + seed کامل
```
